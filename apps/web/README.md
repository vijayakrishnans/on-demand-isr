# apps/web — the site

Vercel's On-Demand ISR template (MIT, `LICENSE.md`) on Cloudflare Workers +
Static Assets: the repository's GitHub issues as pages, read through a GitHub
App and cached with `"use cache"`, regenerated by the App's webhook through
`revalidatePath`. The upstream pages, explanation and stylesheet are kept;
what this app adds is the Workers build, the cache bindings, the repository
taken from the site's own seam, sample issues while no App is connected, a
webhook that stays shut without its secret, and `/api/health`.

- `app/` — the pages: `/` (the issues, under the template's explanation) and
  `[id]` (one issue and its comments, Markdown by `marked`, code by
  `highlight.js`), `api/webhook` (GitHub's deliveries) and `api/health`
- `app/site.ts` — the site's name and the repository it lists (`SOURCE_URL`)
- `lib/github.ts` — the template's GitHub App client: its RS256 JWT
  (`jsonwebtoken`), the installation token, the cached reads
- `lib/settings.ts` — the App's three settings, read per request, and
  whether it is connected
- `lib/sample.ts`, `app/connect-notice.tsx` — what the site shows until an
  App is connected
- `styles/` — the template's stylesheet (`Home.module.scss`, compiled by
  `sass` at build) and its globals

```bash
pnpm dev        # next dev on http://localhost:3000
pnpm build      # next build + opennextjs-cloudflare build → .open-next/
pnpm preview    # wrangler dev over the built Worker: a local R2 bucket, local Durable Objects
```

The cache's bucket is not hand-written. `wrangler.template.jsonc` names it as
a wiring token; `wrangler.jsonc` is that template rendered from
`wiring.fixture.json` (placeholder names, for local work and verification),
and every deploy renders it again from the name the `cloudflare-r2` Terraform
root published for the environment (`component.yaml`'s `buildCommand`).

## The GitHub App

| `GITHUB_APP_ID` and `GITHUB_APP_PK_PEM` | `/` and `/<number>` | `/api/webhook` |
| --- | --- | --- |
| unset (a fresh deploy) | the sample issues, under a notice that says how to connect an App | 503 until `GITHUB_WEBHOOK_SECRET` is set; then 400 to any delivery whose signature does not match |
| set (put on the Worker by the deploy) | the repository's issues, cached in R2 (`"use cache"`) | a signed delivery revalidates `/` and the issue's page |

Connecting an App is three Orun secrets and a redeploy — the repository's
README, "Connecting a GitHub App".
